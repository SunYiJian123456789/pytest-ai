# shopping 后端接口清单与用例对照

被测服务：`http://127.0.0.1:8080`，统一响应结构 `{"code": 200, "message": "success", "data": ...}`。
管理端接口由 `AdminAuthInterceptor` 拦截，除登录外均要求 `Authorization: Bearer adm_...`；用户端购物车与支付要求用户 token。

## 越权（IDOR）实测行为

用户端资源归属全部由服务端从 token 解析，客户端可控的资源 id 只有购物车项 `id`。

| 攻击方式 | 实际响应 | 副作用 |
| --- | --- | --- |
| `PUT /api/cart/{他人项 id}`（改 99 / 改 0 / 改负数） | `HTTP 200` + `code 200` + `success` | 无（SQL 带 `AND user_id`） |
| `DELETE /api/cart/{他人项 id}` | `HTTP 200` + `code 200` + `success` | 无 |
| `GET /api/cart` / `DELETE /api/cart` | 只返回 / 只清空自己的 | 无 |
| `POST /api/pay`（自己车为空） | `code 400` +「购物车为空」 | 不会去结算他人车 |
| `GET /api/pay/records` | 只返回自己的订单（含 `userId`） | 无 |

注意：越权写操作返回 `success` 而不是 403/404——安全上没问题（数据未变），但客户端
无法区分「改成功了」和「这条根本不归你」，属可观测性欠缺，测试据此只断言副作用。

## 已知接口行为（测试据此断言）

1. 登录接口会把 `passwordHash` 置为 `null` 但**仍保留该字段**，因此断言为空值而非字段不存在。
2. 商城商品详情 `/api/products/{id}` 会过滤下架商品；管理端详情 `/api/admin/products/{id}` 不会。
3. `POST /api/upload` 未带 multipart 文件时，Spring 在进入 Controller 前拒绝，返回 500（框架默认错误），不是业务码 400。
4. 未登录访问管理端接口返回 HTTP 401 + `code=401` + 「管理端未登录或登录已过期」。
5. 用户端 token 与管理端 token 双向不可混用。
